# ADR-0005: The kernel's C interface

Status: Accepted
Date: 2026-10-03
Milestone: M2

## Context

From M2 the kernel runs inside Unreal as a DLL on its own threads (plan §3.1, §9: in-process,
C ABI through `cbindgen`, `catch_unwind` at every exported function). The same boundary schema
crosses it as crosses the WebSocket (ADR-0001), so that recording, multi-viewer and a later move
out of process stay open. Changing the interface after an Unreal plugin is built against it means
changing both sides at once, so it is expensive to reverse.

Reports read: 01-06 (embedding a Rust library in an Unreal plugin), 01-07 (streaming state to a
renderer) and 14-10 (web UI in Unreal). Their main points:

- **Load explicitly and negotiate.** Load the `cdylib` at runtime, resolve one export that hands
  back a versioned table of functions, and check the ABI version and structure sizes before
  creating anything (01-06 §2.5). Keep the ABI version separate from the save schema version and
  the build (§2.4).
- **Rust owns the world and its threads; Unreal owns presentation.** Neither reaches into the
  other's objects. The handle is a thread-safe control object, not a way to a `&mut World`
  (§3.1, §4.1).
- **Two delivery policies.** Commands and authoritative notifications are ordered and never
  dropped; presentation snapshots are latest-value and may be skipped (§3.3; 01-07 §1.2).
- **Copy snapshots into caller memory** rather than lending Rust buffers; return "nothing new" or
  "buffer too small" at once instead of waiting (01-06 §3.4–3.5).
- **Narrow, fixed-layout types.** Fixed-width integers, explicit-length byte strings, opaque
  pointers, integer status codes; no Rust or C++ containers across the boundary. Inputs are
  borrowed for the call, outputs go to caller buffers, and each side frees only what it
  allocated (§4.1–4.2).
- **Catch panics inside, then fault the kernel.** `catch_unwind` does not repair state, so a
  caught panic stops the kernel; it is not crash isolation (§4.3).
- **Load once.** Replacing the DLL in a running editor is a separate, later feature (§5.1).
- **Panels.** A local WebSocket is fine for development and an external inspector but needs
  loopback binding, a per-session token and origin checks (14-10 §4.5); the frontend should not
  care which transport it uses (§4.3).

## Decision

### 1. The library

- A crate `civ-ffi` builds the `cdylib` **`tce_kernel`** (`tce_kernel.dll`, `libtce_kernel.so`,
  `libtce_kernel.dylib`). It is a transport for the same engine thread `civ-host` runs
  (`civ_host::engine`), not a second kernel: worlds, saves, autosave and crash recovery behave
  the same.
- Its C header, `crates/civ-ffi/include/tce_kernel.h`, is generated by `cbindgen` and committed.
  A test regenerates it and fails if it differs (`TCE_BLESS=1` rewrites it). Never edit it.
- `unsafe` is denied workspace-wide except in two places: the generated FlatBuffers code and the
  exported functions of `civ-ffi`. Every `unsafe` block there has a `SAFETY:` comment.
- Panics unwind (`panic = "abort"` is never set), so they can be caught.

### 2. One export, one table

```c
int32_t tce_get_api(uint32_t abi_major, TceApiV1 *out, size_t out_size);
```

- `abi_major` must be `TCE_ABI_MAJOR` (1), and `out_size` at least the size of the 1.0 table;
  otherwise the call returns `TCE_INCOMPATIBLE` and writes nothing.
- The table starts with `struct_size`, `abi_major` and `abi_minor`, then function pointers.
  Later minors only **append** functions; a host compiled against a larger table treats the
  functions past `struct_size` as missing. Removing or changing a function is a new major.
- The host keeps its own copy of the table and calls only through it. Nothing else is exported.

### 3. Functions of ABI 1.0

| Function | What it does |
|---|---|
| `versions(out)` | ABI, wire schema, save schema and content API versions (`TceVersions`). |
| `create(config, out)` | Loads the content, opens the saves folder and starts the engine thread. Returns a kernel even when it could not start: its `status` is then `TCE_FAILED` and `last_error` says why. Only a null or malformed argument returns no kernel. |
| `destroy(kernel)` | Stops the panel server if running, stops the engine (autosaving a changed world and removing the session marker, as `civ-host` does at exit), joins every thread the kernel started, and frees the kernel. |
| `status(kernel)` | `TCE_OK` while running, else `TCE_FAILED` or `TCE_FAULTED`. |
| `last_error(kernel, buf, cap, out_len)` | The last failure, UTF-8. |
| `submit(kernel, frame, len)` | One `commons-wire` frame: a `Command`, `Query` or `Heartbeat` (ADR-0001). Its bytes are copied before the call returns. The reply comes later through `poll`, matched by correlation id. A frame the kernel cannot accept returns `TCE_BAD_FRAME` and queues nothing. |
| `poll(kernel, buf, cap, out_len)` | The next **ordered** frame: `Welcome` first, then `Events`, `Response` and `Error` frames in order. |
| `copy_snapshot(kernel, after, buf, cap, out_len, out_number)` | The latest **replaceable** `Snapshot` frame, if its number is greater than `after` (pass 0 at first, then the last number received). Snapshot numbers only grow for the kernel's lifetime, across world epochs. |
| `serve_panels(kernel, config)` | Serves the web panels and their socket on 127.0.0.1 (section 6). |
| `panel_url(kernel, buf, cap, out_len)` | The address the WebBrowser widget opens, with its port and token; `TCE_NONE` before `serve_panels`. |

Rules common to all:

- **Status codes** are `int32_t`: `TCE_OK` 0, `TCE_NONE` 1 (nothing waiting), `TCE_BUFFER_TOO_SMALL`
  2, and negative failures: `TCE_INVALID_ARGUMENT` −1, `TCE_BAD_FRAME` −2, `TCE_FAILED` −3,
  `TCE_FAULTED` −4, `TCE_INCOMPATIBLE` −5, `TCE_STOPPED` −6.
- **Buffers belong to the caller.** When a frame does not fit, the call returns
  `TCE_BUFFER_TOO_SMALL`, writes nothing but the required size to `out_len`, and keeps the frame:
  the next `poll` returns the same frame; the next `copy_snapshot` returns it or a newer one.
- **Strings and paths** are UTF-8 with an explicit length (`TceBytes`); no NUL is required.
- **Structures** carry `struct_size` first, set by the caller, so later minors can append fields.
- **Threads.** Every function except `destroy` may be called from any thread, concurrently; the
  kernel synchronises internally. No call waits for simulation work: `submit` queues, `poll` and
  `copy_snapshot` return at once. `create` and `destroy` block (loading content; saving and
  joining). `destroy` must not race any other call on the same kernel, and the kernel must not be
  used afterwards.
- **Panics** in an exported function are caught: the kernel becomes `TCE_FAULTED`, later calls
  return `TCE_FAULTED` (`destroy` still works), and `last_error` gives the panic message. A panic
  on the engine thread is already contained there (it drops the world and offers the last good
  save for recovery, as in `civ-host`).
- **One kernel per saves folder** at a time; the folder's session marker is the engine's.

### 4. Frames

- The frames are ADR-0001's, byte for byte: the same envelope, schema identity, epochs and
  sequence numbers per kind as on the WebSocket. Over the C interface there is no `Hello`:
  `tce_get_api` and `versions` do the negotiating, so the first ordered frame is the host's
  `Welcome`, followed by the recent events. A `Hello` submitted anyway is accepted and ignored.
- Snapshots are delivered only through `copy_snapshot` and ordered frames only through `poll`, so
  a slow reader can skip snapshots but never misses an event or a reply.

### 5. What the plugin does with it (M2, on the Windows PC)

The Unreal plugin loads the DLL from its own folder with `FPlatformProcess::GetDllHandle`,
resolves `tce_get_api`, checks the versions, creates one kernel per world session, copies the
snapshot and polls once a frame on the game thread, submits commands from user input, and
destroys the kernel before the module unloads. It keeps the DLL loaded until the process exits.

### 6. Panels in Unreal

`serve_panels` serves the web shell and the observer socket on 127.0.0.1 from inside the DLL, so
the WebBrowser widget shows the same panels as the browser (plan §3.1). The socket requires a
token generated per kernel (passed in the page address) and refuses pages from other origins;
`civ-host` refuses other origins too. A native JavaScript binding can replace the socket later
without changing the panels, which talk through one client module.

## Consequences

- Unreal, tests and any other host drive the kernel through one small, versioned surface, with
  the same frames the web observer already uses; the panels do not change.
- A C harness test loads the library dynamically, as the plugin will, and checks that C and Rust
  agree on every structure's size and field offsets. Rust tests drive the same functions.
- Snapshots are copied every frame the host asks for one. At M1's sizes that is a few kilobytes;
  01-06's arithmetic puts 50,000 people at about 3 MB a copy, to be measured in M2.
- Forbidden: exporting anything but `tce_get_api`; Rust or C++ containers, callbacks into the
  host, or borrowed kernel memory across the boundary; changing a 1.x function or structure
  layout (append only); unloading the DLL while a kernel exists.

## Alternatives considered

- **Import-linked or delay-loaded DLL.** Simpler calls, but it hides version negotiation and
  makes replacing the DLL in the editor harder (01-06 §1).
- **Static library.** Every kernel change relinks the plugin; contrary to the plan's deployment.
- **A generated C++ bridge (CXX) or an Unreal–Rust framework.** More machinery than a dozen
  functions need, and bindings to engine internals carry their own upgrade burden (01-06 §1).
- **Zero-copy snapshots** lent to the host. Needs release obligations across threads and DLL
  lifetime; to be considered only if copying measures too slow (01-06 §3.4, §4.2).
- **Callbacks from the kernel into Unreal** for events. Thread affinity and lifetime hazards; the
  host polls instead.
- **A separate simulation process.** Better crash isolation, but a second protocol and process
  supervision; kept open by the transport-agnostic frames (01-06 §1).

## Revisit when

- Measured copy and polling time in Unreal exceeds about 1 ms at p99 of a frame at M2's scale.
- The panels move to a native binding or to middleware (14-10's Gameface or CEF evaluation).
- Editor iteration needs the DLL replaced without restarting (shadow copies, 01-06 §5).
